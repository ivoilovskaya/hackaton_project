# Synthetic / Mock Data

Synthetic-набор нужен для воспроизводимой проверки полной цепочки MVP, когда реальных данных недостаточно для точной атрибуции.

Правила метрик и атрибуции находятся в [measurement.md](measurement.md).

## Цель

Проверить цепочку:

```text
channel
→ campaign
→ placement
→ creative
→ touch
→ lead
→ order/purchase
→ attributed revenue
→ ROAS / ROMI
```

## Требования к полному набору

Генерация должна быть воспроизводимой с фиксированным `seed`.

Минимальный масштаб:

- 20 channels;
- минимум 2 placements на channel;
- минимум 3 creatives в наборе;
- несколько campaigns и courses.

## Обязательные сценарии

Набор должен содержать:

- placement без продаж;
- placement без лидов;
- несколько касаний одного пользователя;
- Last Touch с однозначным последним источником;
- Linear attribution с несколькими источниками;
- покупку без рекламного касания → Organic / Direct;
- касание старше 30 дней;
- касание ровно на границе окна;
- повторную покупку;
- касания до и после предыдущей покупки;
- частичный возврат;
- полный возврат;
- отменённый/неоплаченный заказ;
- дубликат события;
- нулевую стоимость placement;
- неизвестную стоимость `null`;
- несколько курсов в одном заказе.

## Контрольные проверки

### Ключи и связи

- уникальность первичных ключей;
- все внешние ID существуют;
- touch не происходит раньше publication_time;
- purchase_time не раньше соответствующего пользовательского события;
- `refunded_amount >= 0`;
- `refunded_amount <= amount`.

### Атрибуция

Для Last Touch:

- одна покупка получает максимум один рекламный placement;
- вся attributed revenue покупки относится последнему валидному касанию.

Для Linear:

- сумма весов по покупке равна `1`;
- attributed revenue распределяется между всеми валидными касаниями.

Для всего набора:

```text
attributed revenue
+
Organic / Direct revenue
=
total net revenue
```

с учётом правил включения покупок.

### Метрики

- нет двойного учёта стоимости размещения;
- уникальные buyers/leads пересчитываются из событий;
- деление на ноль возвращает `null`;
- неизвестная стоимость не трактуется как нулевая;
- полностью возвращённая успешная покупка имеет `net_revenue = 0`.

## Маркировка

Все synthetic/mock записи должны иметь явный признак, например:

```text
is_synthetic = true
```

Их нельзя смешивать с реальными продажами в одном итоговом показателе без явного разделения.
