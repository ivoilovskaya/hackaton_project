# Правила измерения и атрибуции

Этот документ описывает только правила расчёта маркетинговых показателей и атрибуции выручки. Архитектура бота, роли пользователей, структура интерфейса и схема базы данных описываются отдельно.

## Единицы анализа

Результаты можно агрегировать по:

- `channel`;
- `campaign`;
- `placement`;
- `creative`;
- `course`.

Базовая единица рекламных расходов — отдельное `placement`. Метрики более высокого уровня считаются агрегированием исходных событий, а не простым сложением уже рассчитанных строк.

## Окно атрибуции

Для MVP используем окно атрибуции **30 дней** до покупки.

В расчёт попадают только рекламные касания пользователя, которые произошли не позже покупки и находятся внутри окна атрибуции.

Если у пользователя нет подходящего рекламного касания, покупка относится к **Organic / Direct** и не получает рекламную стоимость.

При одинаковом времени касаний используется стабильное правило сортировки по `touch_id`, чтобы результат был воспроизводимым.

### Повторные покупки

Для повторной покупки учитываются касания после предыдущей успешной покупки пользователя и до текущей покупки, но не старше 30 дней.

Это не позволяет одному старому рекламному касанию автоматически получать всю последующую выручку пользователя.

## Модели атрибуции

### Last Touch

Вся атрибутируемая чистая выручка покупки относится к последнему подходящему рекламному касанию.

Для одной покупки:

```text
attribution_weight = 1
```

у последнего касания и `0` у остальных.

### Linear

Чистая выручка покупки делится поровну между всеми подходящими рекламными касаниями в окне.

Если перед покупкой было `N` касаний:

```text
attribution_weight = 1 / N
attributed_revenue = net_revenue × attribution_weight
```

Сумма долей одной покупки должна быть равна `1`.

В Linear одна покупка может быть связана с несколькими размещениями. В Last Touch — только с одним.

## Атрибуция лида

Источник лида определяется отдельно от источника покупки.

Для лида выбирается последнее подходящее рекламное касание пользователя до `lead_time` в пределах окна атрибуции. Поэтому источник лида и источник последующей покупки могут различаться.

## Учёт покупок и возвратов

В расчёт включаются успешные покупки.

```text
net_revenue = amount - refunded_amount
```

Неоплаченные и отменённые заказы не включаются.

Частичный возврат уменьшает чистую выручку исходной покупки. Полностью возвращённая успешная покупка остаётся в количестве покупок и покупателей, но её чистая выручка равна `0`.

Каждая покупка идентифицируется уникальным `purchase_id`.

## Метрики

| Метрика | Правило расчёта |
|---|---|
| Переходы | Количество уникальных `touch_id` |
| Посетители | Количество уникальных пользователей среди переходов |
| Лиды | Количество уникальных пользователей с лидом |
| Покупатели | Количество уникальных пользователей с успешной покупкой |
| Покупки | Количество уникальных успешных `purchase_id` |
| Total revenue | Сумма чистой выручки всех включённых покупок |
| Attributed revenue | Сумма чистой выручки, распределённой на рекламные касания выбранной моделью |
| Organic / Direct revenue | Чистая выручка покупок без подходящих рекламных касаний |
| Marketing cost | Сумма стоимости соответствующих рекламных размещений |
| CPL | `marketing_cost / leads` |
| Стоимость покупателя | `marketing_cost / buyers` |
| Conversion to lead | `leads / visitors × 100%` |
| Conversion to purchase | `buyers / visitors × 100%` |
| ROAS | `attributed_revenue / marketing_cost` |
| ROMI | `(attributed_margin - marketing_cost) / marketing_cost × 100%` |

Если знаменатель равен нулю, показатель считается неопределённым (`null`), а не нулём.

Неизвестная стоимость рекламного размещения также хранится как `null`, а не `0`.

## ROAS и ROMI

ROAS можно рассчитывать по атрибутированной выручке:

```text
ROAS = attributed_revenue / marketing_cost
```

Для ROMI нужна информация о маржинальности:

```text
attributed_margin = attributed_revenue × margin_rate

ROMI =
(attributed_margin - marketing_cost)
/
marketing_cost
× 100%
```

Если реальная маржа неизвестна, показываем ROAS, а ROMI оставляем неопределённым. Тестовое значение маржи допустимо использовать только как явно обозначенное demo-допущение.

## Агрегация

Уникальных посетителей, лидов и покупателей для channel, campaign и других уровней нужно пересчитывать по исходным событиям, а не складывать из строк отдельных размещений.

Стоимость размещения нельзя дублировать при соединении с касаниями, покупками или креативами.

ROMI по отдельному creative рассчитывается только если определён способ распределения стоимости размещения между креативами.

## Контрольные условия

Для расчёта должны выполняться следующие проверки:

- одна покупка не учитывается дважды;
- в Last Touch сумма атрибутированной выручки покупки относится ровно к одному рекламному источнику;
- в Linear сумма весов по покупке равна `1`;
- `attributed revenue + Organic / Direct revenue = total net revenue` для включённого набора покупок;
- возврат не может быть меньше `0` или больше исходной суммы покупки;
- при неизвестном знаменателе метрика не подменяется нулём.

## Ограничение интерпретации

Атрибуция показывает, **какому рекламному источнику по выбранному правилу приписана покупка или выручка**, но сама по себе не доказывает incremental effect — то есть что покупка не произошла бы без рекламы.
